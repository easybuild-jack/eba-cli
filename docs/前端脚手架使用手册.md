## 1. 概述

`easybuild-admin` 是一个命令行脚手架（npm 包），用于**一条命令生成 EasyBuild Admin 中后台前端项目**。

它会自动完成以下步骤：

1. **解析模板版本**：查询模板仓库最新正式 Release（不含 pre-release / draft），默认锁定该 tag；
2. **下载模板**：通过 degit 拉取该 tag 的代码快照，不带 `.git` 历史；
3. **替换项目信息**：把生成项目 `package.json` 的 `name`、`description` 改成你输入的值，`version` 重置为 `0.1.0`；
4. **初始化 Git**：`git init` + 首次提交（可选）；
5. **安装依赖**：用你选择的包管理器安装（可选）。

生成的项目是「模板快照 + 你的项目信息」，与模板仓库**没有** git 关联——后续升级模板需要你手动比对或重新生成。

- **适合**：从零开始搭一个中后台项目、需要稳定可复现的模板基线。
- **不适合**：已有项目想接入本模板（请手动对照模板改造，不要覆盖已有目录）。

## 2. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | **>= 18.17.0** | CLI 自身 `engines` 要求；用 `node -v` 检查 |
| 模板开发环境 | 建议 **Node.js 20.9 及以上** | 生成的项目基于 Next.js 16，实际开发请以模板 `package.json` 为准 |
| 包管理器 | yarn 4 / pnpm / npm | 模板默认使用 Yarn 4（`packageManager: yarn@4.7.0`） |
| Git | 可选 | 未安装时自动跳过仓库初始化，不影响项目生成 |
| 网络 | 需访问 `github.com` 与 `registry.npmjs.org` | 下载模板、拉取 CLI 本身都依赖外网 |

> 内网 / 代理环境：请先配置好 `HTTPS_PROXY` 与 npm 代理（`npm config set proxy` / `https-proxy`），否则模板下载会失败；也可以把模板镜像成自己的仓库后用 `--repo` 指定。

## 3. 快速开始

### 3.1 交互式创建（推荐）

```bash
npx easybuild-admin my-project
```

按提示依次填写：项目描述 → 包管理器 → 是否初始化 Git → 是否立即安装依赖。生成完成后按终端提示进入目录启动即可。

> 首次执行 `npx` 会提示 "Need to install the following packages… Ok to proceed?"，输入 `y` 即可；CI 中可用 `npx --yes` 跳过该确认。

### 3.2 一步到位（非交互）

```bash
npx easybuild-admin my-project -d "我的管理后台" --pm yarn -y
```

`-y` 表示全部使用默认值，不再弹任何问题。

### 3.3 只下载模板

```bash
npx easybuild-admin my-project -d "我的管理后台" --skip-git --skip-install
```

### 3.4 生成之后

```bash
cd my-project
yarn install     # 如果创建时跳过了安装
yarn dev         # 模板默认端口 4000，访问 http://localhost:4000
```

典型输出：

```text
  🚀 EasyBuild Admin 项目脚手架
  基于 Next.js 16 + React 19 + Shadcn/ui 的管理后台模板

√ 模板版本: v1.0.0（最新发布版）
√ 模板下载完成
✔ 已更新 package.json 中的项目信息
✔ Git 仓库初始化完成
✔ 依赖安装完成

✔ 项目创建成功! 🎉

  进入项目目录:
    cd my-project
```

> 模板的技术栈详见第 7 节，实际版本以生成项目的 `package.json` 为准。

## 4. 命令与参数

```text
easybuild-admin [project-name] [options]
```

| 参数 | 说明 | 默认值 |
|---|---|---|
| `[project-name]` | 项目名称，同时用作目录名和 `package.json.name` | 交互输入（`-y` 时为 `my-easybuild-app`） |
| `-d, --description <desc>` | 项目描述，写入 `package.json.description` | 交互输入（`-y` 时为固定文案） |
| `--pm <pm>` | 包管理器：`yarn` / `pnpm` / `npm`，其他值直接报错 | 交互选择（`-y` 时为 `yarn`） |
| `--skip-install` | 跳过依赖安装 | `false` |
| `--skip-git` | 跳过 Git 初始化与首次提交 | `false` |
| `-y, --yes` | 全部使用默认值，不进行任何交互（适用于 CI） | `false` |
| `--repo <repo>` | 自定义模板仓库，可用 `#分支或tag` 指定版本 | `easybuild-jack/easybuild-admin-front` |
| `-V, --version` | 输出版本号（读取 `package.json`，当前 `1.1.0`） | — |
| `-h, --help` | 输出帮助 | — |

### 4.1 `[project-name]`

- 必须符合 npm 包名规则：由小写字母、数字及 `-` `_` `.` `~` 组成，不能以 `_` 或 `.` 开头，长度 ≤ 214；作用域形式 `@scope/name` 也支持；
- **命令行传入时同样校验**（不只在交互输入时），非法名称立即退出，不会创建任何目录；
- 若目录已存在：交互模式下会二次确认，**确认覆盖会先清空该目录**；`-y` 模式下直接拒绝并退出 1。

```bash
npx easybuild-admin my-app            # 合法
npx easybuild-admin "My App"          # 非法：含大写和空格，直接退出 1
npx easybuild-admin ../evil           # 非法：含路径穿越，直接退出 1
```

### 4.2 `-d, --description <desc>`

写入生成项目的 `package.json.description`，也会出现在后续的提示中。不传则交互询问。

### 4.3 `--pm <pm>`

只接受 `yarn`、`pnpm`、`npm` 三个值，由 commander 在参数解析阶段校验：

```text
error: option '--pm <pm>' argument 'foo' is invalid. Allowed choices are yarn, pnpm, npm.
```

配合 `--skip-install` 时不会真正安装，但该值仍会出现在「安装依赖 / 启动开发服务器」的提示里。

### 4.4 `--skip-install` / `--skip-git`

分别跳过第 5 步和第 4 步。跳过安装时会在结尾提示你手动执行安装命令；跳过 Git 时不会创建 `.git`。

### 4.5 `-y, --yes`

- 未通过参数提供的选项全部使用默认值：项目名 `my-easybuild-app`、包管理器 `yarn`、初始化 Git = 是、安装依赖 = 是；
- 因此 `-y` 默认**会**初始化 Git 并安装依赖，想跳过请显式加 `--skip-git` / `--skip-install`；
- `-y` 下如果目标目录已存在，**不会覆盖**，直接报错退出（保护已有文件）；
- 与 `npx --yes` 无关：`npx --yes` 是跳过 npx 自身的安装确认，`easybuild-admin -y` 是跳过脚手架的交互。

### 4.6 `--repo <repo>`

- 默认 `easybuild-jack/easybuild-admin-front`；
- 支持 `owner/repo#ref`，`ref` 可以是分支、tag 或 commit，例如：
  - `--repo easybuild-jack/easybuild-admin-front#v1.0.0`（锁定某个发布版）
  - `--repo easybuild-jack/easybuild-admin-front#dev`（拉开发分支）
- 带 `#ref` 时视为「自定义版本」，不再去解析最新 Release；
- 也支持完整 URL（如 `https://github.com/owner/repo`），此时不做 Release 探测，直接拉默认分支。

## 5. 交互流程详解

### 5.1 提问顺序与默认值

| 顺序 | 问题 | 默认值 | 什么情况下会被跳过 |
|---|---|---|---|
| 1 | 请输入项目名称 | `my-easybuild-app` | 命令行已给 `project-name` 或 `-y` |
| 2 | 请输入项目描述 | 固定文案 | 已给 `-d` 或 `-y` |
| 3 | 选择包管理器 | `yarn` | 已给 `--pm`、用了 `--skip-install` 或 `-y` |
| 4 | 是否初始化 Git 仓库 | 是 | 用了 `--skip-git` 或 `-y` |
| 5 | 是否立即安装依赖 | 是 | 用了 `--skip-install` 或 `-y` |

**核心规则**：命令行已给出的参数不再重复提问。

### 5.2 非交互环境（CI / 管道 / 重定向）

如果 stdin 不是 TTY 且仍有问题需要询问，CLI 会立即报错退出，而不是卡住或崩溃：

```text
✖ 当前是非交互环境（stdin 不是 TTY），无法弹出交互式问题
  npx easybuild-admin my-app -d "我的管理后台" --pm yarn --skip-git --skip-install -y
```

CI 中推荐两种写法（任选其一）：

```bash
# 参数齐全 + -y
npx --yes easybuild-admin my-app -d "CI 生成" --pm npm --skip-git --skip-install -y

# 参数齐全（不带 -y 也不会再提问，因为所有问题都已被参数回答）
npx --yes easybuild-admin my-app -d "CI 生成" --pm npm --skip-git --skip-install
```

### 5.3 目标目录已存在的三种情况

| 场景 | 行为 |
|---|---|
| 交互模式 | 询问「覆盖会先清空该目录内的所有文件，是否继续?」，默认否；选是则先删除目录再下载 |
| `-y` 模式 | 直接报错退出 1，不覆盖 |
| 非交互且无 `-y` | 报错退出 1，无法确认是否覆盖 |

## 6. 模板版本策略

### 6.1 默认锁定最新正式 Release

未指定 `--repo ...#ref` 时，CLI 会先访问 `https://github.com/{repo}/releases/latest` 的 302 重定向，解析出最新正式发布 tag（自动排除 pre-release 和 draft），再按该 tag 下载。

- 好处：脚手架产出的项目来自**经过发布验证的稳定代码**，而不是随时变化的分支 HEAD；
- 实现上不调用 GitHub API，**不消耗** 60 次/小时的匿名配额；
- 超时 8 秒。

当前模板仓库的最新发布版是 **`v1.0.0`**。

### 6.2 解析失败时的回退

离线、GitHub 不可达、或仓库还没有任何 Release 时，会打印：

```text
‼ 未能获取最新发布版本，将使用仓库默认分支
```

然后继续按仓库默认分支下载。此时产物不可复现，发布到生产的项目建议改用明确版本：

```bash
npx easybuild-admin my-app --repo easybuild-jack/easybuild-admin-front#v1.0.0
```

### 6.3 指定版本 / 分支

```bash
# 锁定发布版（推荐用于生产）
npx easybuild-admin my-app --repo easybuild-jack/easybuild-admin-front#v1.0.0

# 拉开发分支，跟进最新改动
npx easybuild-admin my-app --repo easybuild-jack/easybuild-admin-front#dev
```

> 带 `#ref` 时 CLI 会直接使用该 ref，不再检查它是否是最新 Release；ref 不存在会报错 `找不到模板版本 "xxx"`。

## 7. 生成的项目

### 7.1 技术栈（模板 v1.0.0）

| 分类 | 内容 |
|---|---|
| 核心 | Next.js 16（App Router / Turbopack）· React 19 · TypeScript 6 |
| UI | Tailwind CSS 4 · Shadcn/ui · Radix UI · Lucide Icons |
| 状态与表单 | Zustand 5 · React Hook Form 7 · Zod 4 |
| 生态 | Axios · Tiptap 3 · @dnd-kit · date-fns · next-themes |
| 包管理 | Yarn 4（`packageManager: yarn@4.7.0`） |

特点：菜单与权限由后端接口下发（前端不写死路由）、内置零后端 Mock 引擎（开发态可直接跑通 CRUD）、内置 30+ 无障碍基础组件与 10+ 业务组件。

### 7.2 目录与脚本

生成项目的完整目录说明见模板仓库的 `docs/项目说明文档.md` 与 `docs/开发文档.md`，常用脚本：

```bash
yarn dev          # 开发服务器，默认 4000 端口
yarn build:prod   # 生产构建
yarn lint         # 代码检查
```

### 7.3 创建后需要改的东西

生成的项目里带了示例业务页面与示例接口地址，正式开发前请按模板文档（`README.zh-CN.md`、`docs/开发文档.md`）清理，重点：

1. `package.json` 的 `name` / `version`；
2. 三个 `.env*` 文件里的接口地址；
3. `src/config/api-url.ts` 的接口路径；
4. 删除 `src/app/base`、`src/app/commodity`、`src/app/order` 等示例页面，以及 `src/api/`、`src/types/` 中对应的示例文件；
5. `src/config/routes.ts` 的图标 / 颜色映射（按后端下发的 `resourceId`）；
6. `src/config/login/login-config.ts` 与 `src/app/layout.tsx` 的品牌信息、`public/favicon.ico`。

> 通用鉴权能力（`src/app/auth/`、`src/app/login/`）可保留复用。

## 8. 常见问题

| 现象 / 提示 | 原因 | 处理 |
|---|---|---|
| `未能获取最新发布版本，将使用仓库默认分支` | 离线、GitHub 不可达，或仓库没有 Release | 网络恢复后重试；或 `--repo ...#v1.0.0` 显式指定 |
| `找不到模板的默认分支：owner/repo` | 仓库地址写错、仓库私有、或已删除 | 检查 `--repo`，确认仓库是公开的 |
| `找不到模板版本 "xxx"` | `#ref` 指定的分支 / tag 不存在 | 用正确的 tag（如 `v1.0.0`）或分支名 |
| `无法下载模板 ...` | 网络中断、代理未配置、GitHub 被墙 | 配置代理后重试，见第 2 节 |
| `仓库地址格式不正确` | `--repo` 少了 `owner/` | 用 `owner/repo` 或 `owner/repo#ref` |
| `模板中缺少 package.json` | `--repo` 指向的不是本模板仓库 | 换回默认模板；已下载的文件会保留供检查 |
| `目录 xxx 已存在，-y 模式下不会自动覆盖` | 目标目录已存在 | 删除旧目录或换项目名；交互模式可确认覆盖（会清空目录） |
| 交互模式提示覆盖后原文件消失 | 覆盖会先清空目标目录 | 覆盖前先备份；或用新目录名 |
| `依赖安装失败` + 日志最后几行 | 网络 / 私有源 / 版本冲突 | 按日志排查；进入项目目录手动执行 `yarn install` 重试 |
| `安装超过 5 分钟，已终止安装进程` | 安装超时（默认 300 秒） | 换更快源或调大超时（见下） |
| `Git 仓库已创建，但首次提交失败` | 未配置 `user.name` / `user.email` | 按提示配置后重新提交 |
| `未检测到 git 命令，已跳过 Git 初始化` | 环境无 git | 安装 git 或忽略（不影响项目生成） |
| `npx` 拉到的还是旧版本 | 本地 npx 缓存 | `npx easybuild-admin@1.1.0 --version` 显式指定版本 |
| Windows 下目录删不掉 / 覆盖失败 | 文件被编辑器或进程占用 | 关闭占用进程后重试 |

**调整安装超时**：

```bash
# PowerShell
$env:EASYBUILD_INSTALL_TIMEOUT_MS="600000"
# macOS / Linux
export EASYBUILD_INSTALL_TIMEOUT_MS=600000
```

单位为毫秒，默认 `300000`（5 分钟）。

## 9. 退出码与输出约定

| 退出码 | 含义 |
|---|---|
| `0` | 生成成功；用户在覆盖确认时选择取消（主动取消视为正常结束） |
| `1` | 参数非法、目录已存在且无法覆盖、模板下载失败、模板内容异常等 |

输出符号约定：日志用 `✔` 成功、`ℹ` 提示、`⚠` 警告（不中断）、`✖` 错误；进度用 spinner，成功 `√`、警告 `‼`、失败 `×`。spinner 输出到 stderr，日志文本输出到 stdout。

## 10. 维护者：本地开发与发布

```bash
npm install        # 安装开发依赖
npm run dev        # 直接运行源码（tsx src/index.ts）
npm run typecheck  # 类型检查（tsc --noEmit）
npm run lint       # ESLint
npm test           # 单元测试（node:test）
npm run build      # 打包到 dist/（tsup，ESM）
```

发布流程：

```bash
npm login                 # 需要 eb-jack 账号；有 2FA 时按提示输入 OTP
npm version 1.1.1         # 递增版本（默认会创建 commit 与 tag）
npm publish               # 自动执行 prepublishOnly：typecheck → lint → test → build
npm view easybuild-admin version   # 确认线上版本
```

注意：

- `dist/` 不进版本库，**必须**由 `prepublishOnly` 或手动 `npm run build` 生成，否则发布的包缺少入口；
- 发布后 registry 的 metadata 会很快更新，但 tarball 走 CDN，可能还需数分钟才能真正下载（实测 1.1.0 约 5 分钟）；
- 已发布的版本号不能复用，改动后必须递增版本。
